# 对标 AdGuard Home 等面板的功能与界面优化

> 前提不变：**非侵入式架构**。系统只读 `/proc/net/nf_conntrack` 的累计计数，
> 用 AF_PACKET 旁路嗅探 `udp/53`，BPF 只放行 DNS 报文，不参与转发、不改防火墙、
> 不做 DNS 服务端、不解析载荷。任何优化都不能推翻这三条。

## 一、能力对照：什么能做、什么不能做

剩下值得补的都是**纯前端、零采集改动**的项目。

## 三、界面层对标

AdGuard Home 的信息层次是「左侧固定导航 → 顶部时间范围 → KPI 卡片 →
带筛选的表格 → 点行下钻」，本系统已完全对齐，并在两处做得更细：

- 所有榜单条目均可下钻（设备 / 域名 / IP / 网段 / 服务类别 / 代理结论），
  详情页含关联设备、按小时趋势、连接时间与上下行明细（见 `WEB.md` 第五次迭代）。
- 下载与上传各自独立排名，避免上行被大下载淹没。

仍可对齐的细节：

- **时间范围**：AdGuard 支持自定义区间，当前只有三档快捷按钮。
  CGI 的 `since` 已接受 60–2 592 000 秒任意值，加一个「自定义」输入即可。
- **导出**：AdGuard 的日志、客户端都能导出 CSV；纯前端 `Blob` 下载，
  不改后端也不改架构。
- **收藏/别名**：设备或域名加星标、自定义备注，存 `localStorage`，
  对多设备家庭很有用。
- **告警**：例如「某设备 1 小时上行超过 X」「出现新的 need_proxy 目标」，
  基于已有字段做站内提示，不需要新增采集。
- **热力图**：Netdata 式的「星期 × 小时」活动热力图，`agg_hour` 已有数据。

## 四、建议路线（按性价比）

**P0（低成本、零采集改动）**
1. 导出 CSV（设备、域名排行、查询日志、代理建议清单）
2. 自定义时间范围 + 记住上次选择
3. 设备/域名收藏与备注（`localStorage`）
4. 总览补「拦截占比趋势」「被拦截最多的客户端」

**P1**
1. 站内告警规则（阈值 + 提示条）
2. 活动热力图（复用 `agg_hour`）
3. 更细粒度趋势（15 分钟桶）——需要改采集聚合粒度

**P2（成本较高，但仍在架构内）**
1. 规则变更影响回放：把 `hp_event` 的时间点与归因变化叠到时间线上
2. 逐设备的「首次出现 / 沉寂 / 重新活跃」时间轴

**明确不做**
拦截生效、黑白名单下发、上游 DNS 切换、按客户端策略、DoH/DoT 内容、
DPI 载荷解析、实时阻断。这些都需要让系统进入数据面，会推翻「旁路、零影响」
这个立身之本；要做应该另起一个过滤类应用，而不是改造 netmon。

### 本轮额外补的（不在原路线图里）

| 项 | 为什么加 |
|---|---|
| 总览「一句话看懂」摘要 | 6 张 KPI 是散的数字，用户得自己拼结论；改成一段话直接说清查询量、成功率、流量、拦截占多少、真正要留意多少次失败、最多的是哪个域名 |
| 拦截榜翻页 | 用户问「做可翻页设计了吗」——没有。后端 15→60 条，前端每页 10 条；「真实解析失败」表头「处理」列原本恒为「排入探测」，改成真实占比 |
| 僵尸文案与死链清理 | 昨天精简四模块后残留：总览「平均响应」KPI 还指向已删的 `network` 视图、通用详情 3 处「服务判断」KPI（后端已不返回 `app/cat`）、判读说明整段还在讲代理探测队列 |
| 告警的可信度约束 | 每条告警都写清「是什么 + 去哪看」，并明确只提示、不改任何配置；阈值固定，不制造噪音 |

### 为什么这些功能不碰架构

| 功能 | 数据来源 | 是否进数据面 |
|---|---|---|
| 收藏 / 备注 | 浏览器 `localStorage` | 否，连服务端都不经过 |
| 站内告警 | 本次已加载的 `summary / block_stats / devices / hp` | 否 |
| 拦截占比趋势 | 已有 `dns_timeline` 的 `n` 与 `blocked` | 否 |
| 被拦截最多的设备 | 已有 `devices[].blocked` 归因计数 | 否 |
| 一周热力图 | 新增 `heatmap`：`SELECT (ts_ms/3600000)*3600000, COUNT(*) FROM dnsq WHERE ts_ms>=近7天 GROUP BY 1` | 否，只读且走 `idx_dnsq_tc` 覆盖索引 |
| 一句话摘要 | 已有 `summary / block_stats` | 否 |

后端只多了一条按小时聚合的只读查询（固定 7 天、最多 200 点），
前端不新增任何请求；CGI 10 秒窗口缓存继续生效。
