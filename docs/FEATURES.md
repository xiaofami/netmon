# 功能模块评估与精简记录（2026-11-07）

用户要求「每个功能模块都仔细评估，没用的就删除」。评估红线始终是
**非侵入式架构**：只读 `/proc/net/nf_conntrack` + AF_PACKET 旁路嗅探 udp/53，
不参与转发、不发探测包、不改防火墙。

## 逐模块评估

| 模块 | 价值判断 | 处置 | 理由 / 代码位置 |
|---|---|---|---|
| conntrack 采样 | 核心，一切流量的来源 | **保留** | `ctsample.c` / `ctparse.c`，5 秒一次，CPU 约 0.08% |
| DNS 被动嗅探 | 核心，唯一能看到查询来源的手段 | **保留** | `dnssniff.c`，BPF 只放行 udp/53 |
| DNS 域名反查 | 核心，让 IP 有名字 | **保留** | `dnsmap.c` |
| 设备身份目录 | 核心，53 台设备全部可读 | **保留 + 增强** | `netmon-report.c` 的 `load_catalog()`，本轮加按 MAC 归并、多网卡区分、静态未生效判定 |
| 客户端列表 / 详情 | 核心，可下钻 | **保留 + 增强** | 本轮加翻页、状态徽章、流量趋势图 |
| 流量排行（设备 / 域名 IP / 上下行） | 高，回答谁在占带宽 | **保留** | `emit_traffic()`，已去掉服务标签 |
| 查询日志 / 域名排行 | 高，排查 DNS 问题 | **保留 + 增强** | 加归因筛选、翻页、CSV 导出 |
| 广告拦截归因 + 规则同步 | 高，把「解析失败」解释清楚 | **保留**（改为可选） | `hprules.c`，homeproxy 未安装时安静降级 |
| 规则变更历史 | 中，用户明确要求过「规则变化要知悉」 | **保留** | `hp_event` 表 |
| 系统状态 / 接口统计 / 每日总量 | 中高，对标 pfSense Dashboard widget | **本轮新增** | `emit_sysinfo()`，纯读 `/proc` 与 `agg_day` |
| 通用详情下钻 | 高，几乎所有榜单一一点开 | **保留** | `detail.c` |
| 皮肤（6 套） | 中，观感与可访问性 | **本轮新增** | `www/index.html` CSS 变量组 |
| CSV 导出 / 自定义时间 / 全局搜索 | 中，对标 OPNsense 导出能力 | **本轮新增** | 纯前端，零后端开销 |
| 应答分布环形图 | 中，设备详情页一眼看应答构成 | **保留** | 本轮修正数字居中 |
| **隐私观察** | 低，只能给线索且极易误报 | **删除** | 源码移入 `src/deprecated/`，界面与采集全部移除 |
| **服务类别识别** | 低，只靠域名关键词/端口推测，准确率差 | **删除** | `apps.*` 停用，服务分布/徽章/服务详情一并移除 |
| **线路质量主动探测** | 低，口径易误导且产生额外出站流量 | **删除** | `probe.*` 停用，采集进程不再跑 `run_probe()` |
| **代理可达性探测 / 加规则建议** | 低，靠 HTTP 状态码判定误报多 | **删除** | `reach.*` 停用，KPI/面板/verdict 详情移除 |
| 重复的「目的网段」面板 | 低，两个视图各有一份 | **合并** | 只保留流量排行里的一份 |
| `cmd_probe` / `cmd_prune` CLI | 低，随探测功能失去意义 | **停用** | 保留函数体供运维排查，不再写入数据 |

## 本轮删除量

- `netmon-report.c`：-196 行（服务类别 + 隐私观察）、-45（探测质量）、-36（代理探测）
- `netmon.c`：-146（run_probe）、-8（cfg）、-14（调度）
- `detail.c`：-115（emit_app）、-46（verdict 分支）
- `www/index.html`：-36 -9 -9 -15（视图与面板）、-62 -33（渲染函数）等
- 停用源码归档到 `src/deprecated/`，`Makefile` 已移除编译

## 保留但明确不做的能力

AdGuard Home 式「真正拦截 / 黑白名单下发 / 上游 DNS 切换」、
nDPI 式「抓全量载荷识别协议」、实时阻断、按客户端策略 —— 都需要让系统
进入数据面，与非侵入式架构冲突。要做应另起应用，而不是改造 netmon。

## 2026-11-08 补记：此前路线图里欠下的模块

`UX.md` 第六节逐项核账，本轮新增模块的价值判断：

| 模块 | 价值 | 处置 | 数据来源 |
|---|---|---|---|
| 收藏 / 备注 | 高，多设备家庭找设备最快的方式 | **新增** | 浏览器 `localStorage`，零服务端成本 |
| 站内告警 | 高，把「要看懂 6 张 KPI」变成「看 1 条提示」 | **新增** | 已加载指标即时计算 |
| 一周活动热力图 | 中高，一眼看出作息规律与异常时段 | **新增** | 固定 7 天 `dnsq` 小时聚合（覆盖索引） |
| 拦截占比趋势 | 中，判断规则是否持续生效 | **新增** | 已有 `dns_timeline` |
| 被拦截最多的设备 | 中，定位哪台设备广告请求最多 | **新增** | 已有 `devices[].blocked` |
| 一句话摘要 | 高，用户明确说过「数字不直观」 | **新增** | 已有 `summary / block_stats` |
| 拦截榜翻页 | 中，用户直接点名 | **新增** | 已聚合的 `g_bad[]`，仅提高返回条数 |
| 15 分钟粒度趋势 | 低，与存储/性能目标冲突 | **暂缓** | — |
| 实时逐条查询流 | 低，需采集侧推送 | **不做** | 会推翻旁路架构 |

同时清掉上轮精简后的残留：`network` 死链、3 处「服务判断」空 KPI、
判读说明里的代理探测段落、恒定不变的「排入探测」列。
